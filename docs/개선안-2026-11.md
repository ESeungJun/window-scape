# window-scape 개선안

점검일 2026-11-10 · 대상 `main` bcb4170 (0.5.0) · 저장소는 고치지 않았다.

## 한 줄 정의

바탕화면 구석에 늘 띄워 두는 작은 창. 그 너머 로우폴리 풍경이 지금 날씨·시간대·계절대로 바뀐다. 날씨 정보를 "읽는" 것보다 창밖을 "보는" 느낌을 원하는 macOS·Windows 사용자가 쓴다.

## 컨셉·의도

- 근거: `README.ko.md`, `docs/기획서.md`, `docs/설계서.md`, `docs/결정기록.md`.
- 출발점은 Pascal Mager의 "Blender + Three.js + 날씨" 릴스. 아이디어만 빌리고 모델·코드는 새로 만들었다.
- 목표 세 가지(기획서 목표 표): 늘 띄워 둘 만큼 가볍게, 미니어처처럼 보이게, 오래 봐도 편하게.
- 그래서 고른 것: Tauri 위젯(설치 파일 20MB 안쪽), Blender 스크립트 모델, "하늘빛·틈 그늘은 굽고 해만 실시간", 위젯일 때 30fps 상한.
- 배포: GitHub Releases(맥 arm64·x64 dmg는 Developer ID 서명 + 공증, Windows x64는 서명 없음), Tauri 자동 업데이트. 웹 판은 개발용. 수익 모델 없음. 날씨는 키 없는 Open-Meteo.
- 기획서 "나중"에 재질·조명 개선(가중 법선, PMREM, 꼭짓점 그라데이션, 틸트시프트·블룸)이 원격 `feat/material-quality` 브랜치에만 있고 합쳐지지 않았다고 적혀 있다. 브랜치가 원격에 있는 것은 확인했다(`git branch -a`). 내용은 보지 않았다.

## 구조와 스택

- Three.js 0.186 + three-mesh-bvh · TypeScript 7 · Vite 8 · Tauri 2(Rust). 프레임워크 없음.
- `tools/blender/*.py`(4,336줄): 모델을 전부 스크립트로 만든다(수작업 없음). `lib.py`가 재질·도형·굽기·내보내기, `look.py`가 나무·집·소품·동물, `tile.py`가 네모 땅·먼 풍경·받침, 테마별 스크립트가 배치.
- 내보내기(`lib.py:681-782`): 노드 얼룩·띠를 꼭짓점 색으로 새김 → 정적 물체를 하나로 합침 → 하늘빛·틈 그늘 라이트맵 굽기(`lib.py:613-678`) → glb(Draco) + `layout` extras(강 경로·불빛·길·땅 높이 격자).
- `public/models/<테마>.glb` + `<테마>_light.webp`(2048², ffmpeg libwebp 품질 90).
- `src/scene/world.ts`: 렌더러·카메라·해·안개·프레임 루프. `baked.ts`가 라이트맵에 하늘빛을 곱하는 셰이더 패치.
- `src/scene/{env,sky,clouds,precipitation,water,kit}.ts`: 연출 값, 하늘 돔·환경광, 구름, 강수, 물, 공용 도구.
- `src/main.ts`: 상태·장소·예보 불러오기·UI 연결. `src/data/weather.ts`: Open-Meteo.
- `src-tauri/`: 트레이, 창 배치, 위치, 플러그인(window-state·autostart·updater·process).
- 흐름: Open-Meteo → `main.ts updateScene` → `World.setSelection` → `composeEnv` 목표값 → 프레임마다 보간 → 테마·하늘·구름·강수가 읽음.

### 🟠 체감되는 결함·성능 (10)

**1. 창이 가려지거나 숨겨져도 계속 그린다**

- 지금 문제: 프레임 루프는 상한(30fps)만 있고 멈추는 조건이 없다(`src/scene/world.ts:180`, `:448-452`). `visibilitychange`, 창 가림, 포커스에 대한 처리가 프런트·Rust 어디에도 없다(`src/`, `src-tauri/src/` 검색 결과 0건). "바탕화면 고정"은 다른 창 뒤에 깔려 있는 시간이 대부분인 배치다.
- 고치는 방법: (1) `document.visibilitychange`에서 `renderer.setAnimationLoop(null)` / 복귀 때 재개. (2) Rust에서 맥 `NSWindow.occlusionState` 변화를 받아 이벤트로 보내고(Windows는 최소화·가림 판정), 가려지면 멈춤. (3) 전체 화면 앱이 떠 있을 때도 같은 처리.
- 나아지는 점: 하루 종일 떠 있는 위젯이 안 보이는 동안 GPU를 쓰지 않는다.
- 예상 결과: 가려진 동안 `renderer.info.render.frame`이 늘지 않는다.
- WKWebView가 가려진 창의 rAF를 스스로 줄이는지는 확인 못 했다(네이티브 빌드를 돌리지 않음). 줄이더라도 0이 되는지는 실측이 필요하다.

**2. 그림자 맵을 매 프레임 다시 그린다**

- 지금 문제: 그림자 내는 메시 251~314개를 프레임마다 그림자 맵에 그린다. 해 방향은 시간대 프리셋 4개로만 바뀌고(`env.ts:43-46`), 그림자 중심은 1 단위 격자에 붙는다(`world.ts:466`). 바뀌는 것은 나무 흔들림과 자동차·성 같은 움직이는 것뿐이다. 실측으로 island 호출의 43%, 삼각형의 49%가 그림자다.
- 고치는 방법: `renderer.shadowMap.autoUpdate = false`. 해 방향·그림자 중심·테마·화질이 바뀐 프레임과, 그 밖에는 3프레임에 한 번(30fps 기준 10Hz)만 `needsUpdate = true`. 바람이 약하고(`env.wind < 0.3`) 움직이는 것이 타일 밖이면 더 낮춘다.
- 나아지는 점: 흔들리는 나무 그림자는 10Hz여도 티가 나지 않고, 그리는 양이 3분의 1 가까이 준다.
- 예상 결과: island 평균 호출 414 → 약 290, 삼각형 516,168 → 약 350,000(3프레임 중 2프레임은 234호출·262,342삼각형).

**3. 늘 떠 있는 위젯인데 고성능 GPU를 요구한다**

- 지금 문제: `powerPreference: 'high-performance'`(`world.ts:95`). 그래픽이 둘인 인텔 맥(x64 dmg를 배포한다)에서는 외장 GPU를 계속 깨워 둔다.
- 고치는 방법: 위젯(`isDesktopApp`)일 때 `'low-power'`, 웹 쇼케이스는 지금 값. `World` 생성자에 인자로 넘긴다.
- 나아지는 점: 인텔 맥북의 배터리·발열.
- 예상 결과: 인텔 맥 활성 상태 보기의 "고성능 GPU 필요" 열이 "아니요".
- 인텔 맥 실기기에서는 확인 못 했다.

**4. 구름이 덩이마다 메시 하나다**

- 지금 문제: 하늘 구름 18개가 덩이 4~7개씩(72~126개), 구름바다가 110개. 전부 낱개 `THREE.Mesh`이고 도형은 `IcosahedronGeometry(1, 3)`(1,280삼각형)이다(`src/scene/clouds.ts:31-66`). 하늘 구름은 그림자도 낸다(`clouds.ts:41`). 하늘섬에서 다 보이면 최대 236호출·약 30만 삼각형(그림자 패스 별도)이다. 코드에서 계산한 값이고, 실측 island 414호출 중 모델이 143프리미티브인 것과 맞는다.
- 고치는 방법: 하늘 구름·구름바다를 각각 `THREE.InstancedMesh` 하나로. 나타남은 인스턴스 행렬의 크기로(지금도 `scale`로 한다, `clouds.ts:82`). 구름바다는 detail 2(320삼각형)로 낮춘다. 구름 그림자는 실제 그림자 대신 아래 3D 고도화안의 "흐르는 구름 그늘"로 바꾸면 그림자 패스에서 빠진다.
- 나아지는 점: 호출이 2개가 된다.
- 예상 결과: island 호출 414 → 180 안팎(2번과 별개).

**5. 쓰이지 않는 후처리 체인이 항상 만들어진다**

- 지금 문제: `EffectComposer` + `GTAOPass` + `OutputPass`를 생성하고(`world.ts:102-117`) 창 크기가 바뀔 때마다 크기를 맞춘다(`world.ts:414`, `:436`). 그리는 조건은 `this.useComposer && !this.stage.baked`(`world.ts:521`)인데 다섯 테마가 모두 `baked = true`다(`island.ts:31`, `diorama.ts:81`). 실측에서도 `useComposer: true`, `baked: true`로 합성기는 한 번도 그리지 않는다. 화면 크기 × 배율의 렌더 타깃 여러 장이 쓰이지 않은 채 잡혀 있고 번들에도 들어간다.
- 고치는 방법: 합성기·GTAO 코드와 `useComposer`를 지운다. 굽지 않은 테마를 다시 만들 계획이 있으면 그때 `import()`로 불러온다.
- 나아지는 점: GPU 메모리, 리사이즈 비용, 번들 크기.
- 예상 결과: `index.js` 감소(GTAO·Composer·Pass 모듈), `world.ts`의 품질 분기 단순화.

**6. 모델 재질이 전부 양면이다**

- 지금 문제: 다섯 glb의 재질 249개가 모두 `doubleSided`(실측). Blender 재질을 만들 때 뒷면 숨김을 켜지 않아서다(`tools/blender/lib.py:65-102` `mat()`). three.js는 이를 `DoubleSide`로 읽어 닫힌 도형(집·나무·바위)의 뒷면까지 그리고, 그림자 맵에도 양면으로 넣는다.
- 고치는 방법: `mat()`·`banded()`에서 `m.use_backface_culling = True`. 한 겹 면(돛·천·꽃·풀·깃발)만 인자로 예외. 다시 내보낸다.
- 나아지는 점: 조각 셰이더가 도는 픽셀 수와 그림자 패스 삼각형이 준다. 닫힌 도형의 그림자 줄무늬(양면 그림자)도 줄 수 있다.

**8. 밤 불빛용 점광이 낮에도 모든 픽셀에서 계산된다**

- 범위: `env.ts`에 `wet`, `baked.ts patch`(젖은 면 어둡게·약한 반사), `tile.py`(웅덩이 자리 꼭짓점 속성).

impeccable의 비평 관점(이 제품만의 모양인가, 위계, 상태, 감정 흐름)으로 봤다.

### "AI가 만든 티"가 나는 지점

- **유리 패널 + 대문자 자간 로고 + 얇은 큰 숫자**: `.glass`(`backdrop-filter: blur(18px) saturate(1.3)`, `style.css:53-57`), `WINDOW SCAPE`(`letter-spacing: 0.18em`, `style.css:62-70`), 기온 92px 굵기 300(`style.css:90`). 요즘 날씨 앱 틀 그대로다. 풍경은 손으로 빚은 점토 미니어처인데 UI는 유리와 헬베티카풍이라 서로 다른 세계다.
  → 방향: UI를 "창가의 물건"으로. 기온은 창턱의 작은 온도계나 창유리에 붙인 메모, 7일 예보는 창턱에 줄지어 놓인 작은 카드. 로고는 위젯에서 지운다(이미 내 창이다).
- **도구 막대가 늘 떠 있다**: 위젯에서 검색·위치·들어가기·설정 아이콘이 풍경 오른쪽 위를 계속 가린다(`style.css:429-432`). 창 위에 마우스가 올라왔을 때와 키보드 포커스가 안에 있을 때만 보이게 한다(`.app:hover`, `:focus-within`). README의 "작으면 섬과 기온만"과도 맞는다.
- **아이콘이 얇은 선 한 벌**: `index.html`의 인라인 SVG 4개가 모두 같은 굵기의 선 아이콘이다. 장면의 덩어리감과 맞추려면 채운 도형 아이콘이 낫다.
- **토스트·배지 문구**: "연결 안 됨 · 이전 정보"(`main.ts:209`)는 상태 코드처럼 읽힌다. "12분 전 날씨예요"처럼 사용자가 알고 싶은 것(얼마나 오래됐나)으로.
- **빈 상태**: 🟠 10. 예보가 없을 때의 어두운 빈 막대와 "--°".

## 확인 못 한 것

- Tauri 네이티브 빌드와 실제 위젯 동작(트레이, 창 배치, 투명 창, 위치 권한, 자동 업데이트). cargo 빌드를 돌리지 않았다.
- 가려진 WKWebView/WebView2 창에서 rAF가 실제로 얼마나 도는지(🟠 1). 전력·GPU 사용률도 재지 못했다. 측정은 M5 Pro 헤드리스 Chrome뿐이다.
- 인텔 맥·Windows 실기기 프레임.
- Blender가 이 기기에 없어 스크립트를 돌리지 못했다. 뒷면 숨김·가중 법선·불빛 굽기·인스턴싱의 결과물 크기와 화면은 예상이다. 라이트맵 굽기에 걸리는 시간도 모른다.
- `gltf-transform draco` 재압축본(A-10)의 화면 품질. 크기만 쟀다.
- 라이트맵 WebP(품질 90, 8비트)의 어두운 틈 띠 현상 여부. 캡처에서 눈에 띄지는 않았다.
- 꼼꼼히 읽지 못한 파일: `src/scene/explore.ts`(675줄), `city.ts`·`castle.ts`·`drive.ts`·`forest.ts`의 움직이는 것 로직, `src/ui/*.ts`, `src-tauri/src/location.rs`, `tools/blender/{city,castle,drive,forest,island}.py`의 배치부. 구조와 일부 줄만 확인했다.
